# Phase 2 backlog (logged during Wave 1, not built)

Ideas raised while building Wave 1. Wave 1 scope is frozen; each row gets copied into the
traceability matrix as a Phase 2 requirement with these acceptance criteria.

| ID (proposed) | Idea | Why | Accept |
|---|---|---|---|
| SUPP-P2-01 | TypeSafe Jev for the Concierge escalation check, A/B against gpt-4o-mini | Built for single-choice classification; ~5× cheaper; confidence score allows gating | Same or better escalation recall and false-escalation rate on the dev escalation set incl. Hinglish cases; calls traced, costed and budget-capped via `run.model` |
| SUPP-P2-02 | Offer a person before handing off (3-way: escalate / offer / answer) | Fin's pattern for anger and vague "agent?" requests; cuts needless handoffs | False escalation lower than the 2-way check on the same conversations, recall unchanged |
| SUPP-P2-03 | Loop detection: same question asked 2+ times → handoff | Built-in trigger in Fin; catches stuck guests the category check misses | Planted-loop eval cases escalate ≥95%, no change on control cases |
| SUPP-P2-04 | Pause the bot after handoff until a person hands back (manual session mode) | Parlant pattern; today the bot keeps replying with reassurance | Messages after handoff go to the human queue, not the agent; resume returns control |
| SUPP-P2-05 | Measure handoff timing, not only whether it happened | "Time to Transfer" (AAAI 2021): too-early wastes staff, too-late frustrates | Eval reports turns-to-handoff vs the labelled turn, with tolerance, n shown |
| SUPP-P2-06 | Audit the escalation categories against real owner-handled chats | Categories are a judgement call; real interventions show what's missing | Every owner-handled conversation in the private sample maps to a category, or a new one is added |
| SUPP-P2-07 | Price negotiation / discount requests (36 of ~1,100 real Airbnb questions) | Frequent real ask; Palmgrove has fixed rates today | Policy in KB + routed as policy_exception; eval cases added |
| LEAD-P2-01 | Real WhatsApp sends via the Meta test number | Blocked on 2026-10-20: Meta business verification pending and the payment step rejects Indian cards. The adapter (`integrations/messaging/real.py`) is built and tested against fake HTTP; the Dispatcher's WhatsApp rules (24h window, template, allowlist, opt-out, idempotency) are tested on the mock | `make integrations-check` reports `whatsapp: ok` and the hello_world template arrives on an allowlisted phone; one demo lead gets a real WhatsApp reply |
| VOICE-P2-01 | Resume after a false interruption (cough, "mm-hm", background noise) | LiveKit pattern: speech under 0.5 s or with no transcript within 2 s is treated as false and the agent resumes. Not in Wave 1: the eval has no noise, and a 0.5 s minimum would break the 300 ms barge-in target | A noisy-caller audio set shows the agent resuming after backchannels without missing real barge-ins (≤300 ms) |
| VOICE-P2-02 | Stream the reply into TTS while the model is still generating | VOICE-016 misses (non-tool 2.3 s vs 1.2 s; tool 2.2 s vs 1.5 s). Model time (~1.0-1.5 s) is the floor; most of it is time to first token, so streaming saves only ~0.3-0.6 s on non-tool turns and almost nothing on tool turns (the filler waits for the first model call). It means reworking the stop-early step loop, streamed tool calls and redaction on partial text, so it was not worth it inside Wave 1's timebox (ADR v0.4.4) | Non-tool median drops by ≥0.3 s in `make voice-eval` (n=10) with booking assertions unchanged |
| VOICE-P2-03 | Turn-detection sweep: false ends vs added latency, on fixed recordings with a held-out set | Turns ending at a mid-sentence pause cost ~1.4 s each (the agent restarts); a longer silence cap or a transcript gate (LiveKit-style) trades that for latency on every turn. Two readers' points (2026-10-23): a text gate can flip on revised partial transcripts, so gate on final transcripts only; and don't pick settings on the same calls you report. The live simulated caller makes every run sound different, which is noise across a sweep | Caller audio recorded once (incl. deliberate mid-sentence pauses), split dev/test. Replayed through STT + VAD + turn detection only (no LLM). Sweep silence cap × final-transcript window on dev; report p95 turn-end delay vs false-end rate with n; confirm the chosen setting on test |
| VOICE-BUG-01 (Wave 1 known bug) | Moving a booking to a time that overlaps itself fails ("15 minutes earlier" for a 2-hour colour) | The new hold overlaps the booking it replaces, and the no-overlap constraint rejects it as slot_taken; after two such failures the agent transfers (eval call-028, 2026-10-23). The criterion (≥90% booking success) still passes, so it's logged, not fixed in the timebox | A reschedule to an overlapping time on the same stylist succeeds; the old booking is released only on confirm; a concurrent caller still can't take either time |
| VOICE-P2-04 | Multi-day availability in one search ("anything this week?", "the weekend") | Today the caller's words always resolve to one day, so the agent searches day by day: correct (each day has its own count and first/last) but slower and wordier. Raised by readers on the dates write-up (2026-10-23), with two cautions: a sample mistaken for the full list across days, and a window crossing midnight grouped by UTC instead of local time (slots are grouped by the salon's local date today) | `find_slots` accepts a range phrase and returns per-day count, first/last (with stylist) and the window's start/end as fields; an eval set of multi-day questions (incl. a closed day in the range) passes times_grounded and calendar_state |
| VOICE-P2-05 | Run the time check live: verify every time in a reply against the calendar before it's spoken | The eval's times_grounded check (agents/operator/evals/claims.py) caught real made-up times (call-019 offered an unchecked, already-past slot; slot-005 a wrong "latest"). The same code, fed by the turn's find_slots results instead of a pre-call snapshot, could block the reply and make the model try again: "the LLM talks, code decides" applied to its own words | A reply with an ungrounded time is never spoken: regenerated once with the reason, else a safe fallback ("let me check that time"); times_grounded = 100% on the text suite; added latency reported (non-tool and tool turns, n shown) |
| VOICE-P2-06 | Never say "booked" (or "cancelled", "moved") unless the tool confirmed it this turn | call-049 told the caller "you're booked" without calling confirm_booking (no_false_success caught it in the eval, after the fact). A code check on the reply against this turn's tool results would stop it | no_false_success = 100% on the text suite; a scripted model that claims success without confirm_booking is blocked in a unit test |
